# Version Single Source of Truth

Status: implemented. Concerns the versions the runtime base and app images are
built from — Borg 1/2, Python, borgstore, the runtime-base revision, and the agent
package — and how every consumer derives them from one statement of each.
Companion to `2026-07-19-managed-agent-install-layout.md`, which relies on the Borg
version being a single fact.

## Problem

Each of these is a single fact, yet each was written by hand in several places,
and nothing kept the copies in step — so they drifted, and the drift only ever
surfaced at build or run time.

- The **Borg version** appeared in both Dockerfiles' `ARG` lines and again in the
  binary manifest. A manifest-only bump left the image building the old version
  and the installer offering neither.
- The **Python version** was a literal in the Dockerfiles: the app image built on
  `python:3.10-slim` but copied `python3.12/site-packages`, a path a 3.10 image
  does not have — the recipe would not build at all.
- The **runtime-base tag** was a hand-typed string, free to name an image tag that
  need not exist.
- The **agent version** lived in both `pyproject.toml` and
  `agent/borg_ui_agent/__init__.py`. The wheel takes the pyproject value, so
  bumping only `__init__.py` shipped an agent a release behind its own code.

The app version already solved its half of this — it lives once in `VERSION`, and
every consumer derives from it. This extends that discipline to the rest.

## The facts, and their one home

`docker/runtime-base.env` states each primitive fact once:

```
BORG1_VERSION=1.4.5
BORG2_VERSION=2.0.0b21
BORGSTORE_VERSION=0.4.1
PYTHON_VERSION=3.12
RUNTIME_BASE_REVISION=1
```

The tag is not among them: it is a *function* of these values, not a fact (see
below). The revision gets a named home here instead of living only inside a tag
string — it resets to 1 when a Borg version changes (the version already moves the
tag) and is bumped for a recipe-only change that keeps the same Borg versions.

The agent version is a separate lifecycle — it versions the package, not the image
— and stays with the package: `pyproject.toml` is the source, and
`agent/borg_ui_agent/__init__.py` is held in step with it.

## The tag is a function, not a field

`docker/runtime-base-tag.sh` computes the runtime-base tag, in one place, from the
file above:

```
runtime-borg1-${BORG1_VERSION}-borg2-${BORG2_VERSION}-r${RUNTIME_BASE_REVISION}
```

No tag literal lives in any Dockerfile or build script. This is what makes a tag
that names a non-existent image structurally impossible.

## Everything else derives

- **Dockerfiles** take `ARG PYTHON_VERSION` and `ARG BORG*_VERSION` with the file's
  values as defaults, and interpolate them into `FROM python:${PYTHON_VERSION}-slim`
  and the `site-packages` copy paths. The defaults **stay** rather than being
  emptied: an `ARG` with no default forces every caller to pass it, and a plain
  `docker build .` would then produce `python:-slim` / `borgbackup==` and fail.
  Keeping the default makes the versions file the *source* of the default and a
  test its enforcer, so those callers follow the truth with no literal of their
  own.
- **The binary manifest** is generated by `refresh_borg_binary_manifest.py`, which
  reads the versions file rather than a Dockerfile `ARG`; `--latest` writes the
  file (resetting the revision) and regenerates the manifest. Its currency and
  coverage-regression handling are `2026-07-19-managed-agent-install-layout.md`.
- **The agent version** derives at the package boundary: `pyproject.toml` is the
  source; `__init__.py` is kept equal to it.

## What enforces it

Drift stops being unlikely and becomes impossible, because a green build requires
agreement:

- the computed tag equals the versions file;
- every Dockerfile `ARG *_VERSION` default equals the versions file;
- exactly one Python minor version across the Dockerfiles — this would have caught
  the stray 3.10;
- `pyproject.toml` equals the agent `__version__`.

## Non-goals

Changing which Borg or Python versions are built — this is about *where they are
stated*, not *what they are*. The app-version pipeline, which `VERSION` already
single-sources.
