# Browser end-to-end tests

## Why

Unit tests mock the API, Storybook snapshots render components alone, and the
smoke tests in `tests/smoke/` drive the API without a browser. Nothing drives
the real UI against a real backend and a real SSH server. PR #1498 (per-connection
SSH keys) was verified by clicking through it by hand on 2026-11-13. This suite
makes that pass repeatable, starting with those SSH key flows.

## Goals

- One Playwright suite in `frontend/e2e/`, run against the built app served by
  uvicorn on a fresh database, with a real sshd that accepts a password.
- First spec covers the PR #1498 flows: header actions with only the system key,
  adding a generated key, deploying with it, the passphrase error on paste,
  switching a connection's key and redeploying, and deleting keys.
- A CI job that runs it on every PR and uploads the Playwright trace on failure.

## Non-goals

- Cross-browser runs. Chromium only.
- Visual assertions. Argos already owns those.
- Replacing the API smoke tests. E2E checks what a user sees; the smoke tests
  keep checking Borg behaviour.

## Anti-goals

- Running against anyone's real data. The backend always starts on a new
  `DATA_DIR`; the suite never points at the dev container or `:7879`.
- Emitting analytics. Requests to `t.borgui.com` are aborted in the browser and
  the analytics preference is saved as off before any page loads.
- Weakening app code to make tests pass. If MUI transitions stall in headless
  Chromium, the fix is `reducedMotion` in the Playwright config.

## Approaches

1. **Playwright test runner in `frontend/` (picked).** The `playwright` devDependency
   already ships `playwright/test` and the `playwright test` CLI, so nothing new is
   installed. Tests sit next to the code whose labels they read.
2. **pytest-playwright in `tests/`.** Fits the Python smoke tests, but adds a Python
   dependency and a second Playwright install, and the UI labels live in
   `frontend/src/locales/en.json`.
3. **A step inside `smoke-borg-ssh-localhost`.** Reuses the job, but that job runs
   in the runtime-base container (no browser libraries) and a matrix of two Borg
   builds that does not matter for UI flows. Its sshd also forbids passwords,
   which Deploy to Server needs.

## Design

- **Runner:** `frontend/playwright.e2e.config.ts`, `testMatch: *.e2e.ts` (so vitest's
  default `*.spec.ts` / `*.test.ts` glob never picks them up), one worker, Chromium,
  `reducedMotion: 'reduce'`, `trace: 'retain-on-failure'`, base URL from
  `E2E_BASE_URL` (default `http://localhost:8082`). Script: `npm run test:e2e`.
- **Login:** a setup project logs in through the API with `admin` / `admin123` (the
  fresh-DB default), skips the first-login password change
  (`POST /api/auth/password-setup/skip`), saves analytics as off with consent given
  (`PUT /api/settings/preferences`), and stores `access_token` in `localStorage` as
  Playwright storage state. Every test starts logged in with no prompts.
- **State:** the SSH key spec runs serially and builds on itself, the way a user
  would: system key first (generated through the API in setup of that spec), then
  extra keys and connections. A fresh `DATA_DIR` per run is the reset.
- **SSH target:** `tests/e2e/setup-sshd.sh` starts sshd on a given port with one user
  (`borge2e`) allowed to log in by password. CI runs it on the runner; locally it
  runs inside a throwaway `debian:bookworm` container.
- **CI:** a new `e2e-browser` job in `tests.yml` on `ubuntu-latest` (no container):
  downloads `frontend-build-output` into `app/static`, installs `sshpass`,
  `openssh-server` and Python deps, starts uvicorn on :8082 with a fresh `DATA_DIR`,
  runs the suite, uploads `frontend/e2e-results/` and the backend log on failure.
  Listed in `CI / Summary` so it gates merges.

## Left to the builder

- Selectors: prefer roles and English labels from `en.json`; add no test ids unless
  a control has no accessible name.
- Exact assertions for "connected" (the card's status text) and "in use" (the key
  row's connection count).
